# git-guide-time-travel
## 我要回去/回来
### 1. 查看历史提交
要回去，首先得知道你想去哪。先查 **Commit ID（提交哈希值）**!

* **完全查看：**
```bash
git log

```
这会显示详细的提交历史（作者、日期、描述）。按 `q` 键可以退出查看。

* **精简查看（推荐）：**
```bash
git log --oneline

```

每条记录只占一行，长这样：`a1b2c3d [Fix] 修复了登录页面的 Bug`。前面的 `a1b2c3d` 就是你需要的 Commit ID。

* **查看分支演变图（最直观）：**
```bash
git log --oneline --graph --all

```

它会用字符线条画出各个分支交错、合并的历史轨迹。

---

## 2. 回去（穿越到过去）

去过去有两种方法，取决于你的**真实目的**：你是只想“走马观花看一眼”，还是想“推翻历史重来”？

### 方法 A：只想看看或做点测试（安全、推荐）

如果你只是想回到某个版本看看当时的代码，或者做点不影响主线的测试：

```bash
git checkout <Commit-ID>

```

> 💡 **注意：** 这会让 Git 处于“头指针分离”（detached HEAD）状态。你在这个状态下做的修改不会被保存。看完之后，随时可以轻松回来。

### 方法 B：强制完全回去！（彻底抹去历史）

如果你确定未来的某几次提交完全不要了，想让代码彻底回到过去的某个节点：

```bash
git reset --hard <Commit-ID>

```

> ⚠️ **警告：** 这个操作会丢弃该节点之后的所有修改。如果你已经把代码推（push）到了远程仓库，慎用此招。

---

## 3. 如何回来（返回未来）？

如果你用了上面的方法去了过去，要怎么回到你最新（最前沿）的代码呢？

### 如果你是用 `git checkout` 过去的：

非常简单，直接切换回你原本的分支（通常是 `main` 或 `master`）：

```bash
git checkout main
# 或者现在的 git 版本也支持：
git switch main

```

### 如果你是用 `git reset --hard` 过去的，现在后悔了：

这时候 `git log` 已经看不到未来的记录了，很多人在这里会抓狂。别怕，Git 有一颗“后悔药”叫 **引用日志（reflog）**，它记录了你本地电脑上所有的 Git 动作，包括你刚刚的操作。

1. **第一步：召唤后悔药**
```bash
git reflog

```


你会看到一长串记录，类似于：
```text
a1b2c3d HEAD@{0}: reset: moving to a1b2c3d
e5f6g7h HEAD@{1}: commit: [Feature] 新增了支付功能

```


2. **第二步：找到你未来的那个 Commit ID**
在上面找你执行 `reset` 之前的那个提交（比如上面例子里的 `e5f6g7h`）。
3. **第三步：逆天改命，重新穿越回未来**
```bash
git reset --hard e5f6g7h

```


这样，你失去的未来就全部回来了！
